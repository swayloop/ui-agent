# 스킬 작성 원칙 (검증 기준)

`create-skill.sh verify` 가 이 원칙들을 결정적으로 린트한다. 일부는 휴리스틱이라 ⚠ 로만 알린다.

## 1. 라우팅 규칙 같은 설명
`description` 은 Claude/Codex 가 **정확한 순간에 활성화**할 만큼 구체적이어야 한다. 트리거 상황을 적되, 장황하지 않게.
- 좋음: "새 스킬을 만들거나 기존 스킬을 손볼 때 사용한다."
- 나쁨: "스킬 관련 도구." (언제 켜야 할지 모름)

## 2. 결정적 작업엔 결정적 코드
파싱·유효성 검사·정렬처럼 정답이 정해진 일은 모델에게 "주의하라"고 하지 말고 `scripts/` 로 위임한다.
**특히 작업을 끝낸 뒤 결과가 맞는지 스크립트로 검증**한다 (예: 만든 산출물을 다시 읽어 불변식 assert).

## 3. 간결한 SKILL.md — 본문은 라우터다
본문은 짧게, **필요한 문서로 안내하는 내용만** ("무엇을 / 어디서 보라") 둔다.
절차 디테일·규칙·사용법·예시 같은 세부는 모두 필요할 때 로드되는 `references/` 와 `--help` 로 분리한다.

## 4. 스킬당 한 작업
하나의 스킬은 하나의 명확한 작업만. 여러 워크플로우를 욱여넣지 않는다. 그러면 활성화도 정확해진다.

## 5. 구체 예시
추상적 규칙 목록 대신 **실제로 동작한 구체 예시**를 둔다 (`references/example.md`).
